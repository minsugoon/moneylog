# Moneylog 입력 인식(파서) 명세

- 버전: v0.6 / 최종 수정: 2026-10-31
- 변경(v0.6, 2026-10-31): **카드앱 "붙여넣기"를 "화면 캡처 + AI(Claude)"로 변경**, 문자 형식 5종과 실제 샘플 반영, 결과에 **시각·계좌 힌트 구조** 추가, **중복 규칙 개정**(시각 포함·개수 비교·"중복 가능" 후보), 리볼빙 표기 규칙, AI 출력 규칙
- 관련 코드: `src/utils/parsers/` (카드사·은행별 파일 + 테스트), 중복 판정 `src/utils/import*.ts`, 서버 함수 `supabase/functions/parse-capture/`(단계 7-B)
- 관련 기능: F9(카드앱 캡처), F10(문자), F11(엑셀/CSV), F12(중복 방지), F26(AI 이용 안내·한도)

## 1. 입력 방식
| 방식 | 사용자가 하는 일 | 인식 방법 | 결과 | 시기 |
|------|------------------|-----------|------|------|
| 직접 입력 | 폼에 입력 | 없음 | 바로 저장 | 완료 |
| 문자 붙여넣기 | 카드 승인·취소·자동결제 문자를 복사해 붙여넣기 (여러 건 가능) | **규칙(정규식), AI 없음** | 건별 분리 → 미리보기 → 확인 → 저장 | 7-A |
| 통장 문자 붙여넣기 | 통장 출금·입금 문자를 붙여넣기 | **규칙, AI 없음** | 같음. 입금은 기본 해제 | 7-A |
| 카드앱 캡처 | 이용내역 화면을 캡처해 올리기 | **AI(Claude), 서버 함수 경유** | 미리보기 → 확인 → 저장 | 7-B·7-C |
| 엑셀/CSV 업로드 | 카드사에서 받은 파일 선택 | 열 이름 매핑 | 열 매핑 → 미리보기 → 확인 → 저장 | 단계 11 |

문자는 텍스트 붙여넣기가 가장 정확하다. 카톡 캡처 이미지는 개발용 샘플 공유에만 썼다.

## 2. 파서 결과 모양 (모든 파서 공통)
```ts
type AccountHint = {
  issuer: string | null;        // '삼성', '하나', '우리' 같은 문구 속 카드사·은행 이름
  digits: string | null;        // 끝자리. 카드는 2~4자리일 수 있고(하나28 → '28'), 통장은 끝 4자리만
  kind: 'card' | 'account' | null;
};

type ParsedRow = {
  status: 'ok' | 'failed';
  date: string | null;          // 'YYYY-MM-DD'
  time: string | null;          // 'HH:mm'. 문구에 시각이 없으면 null (자동결제 접수 문자, 일부 캡처)
  merchant: string;             // 결제명
  amount: number | null;        // 0 이상 정수(원)
  installment: number;          // 할부 개월, 일시불은 1
  isCancel: boolean;            // 취소 건 여부
  interestFree: boolean;        // 무이자 할부 문구가 있으면 true
  direction: 'expense' | 'income'; // 통장 문자의 출금/입금. 카드는 항상 expense
  accountHint: AccountHint | null; // 등록된 결제수단 자동 선택에 쓰는 힌트
  source: 'sms' | 'capture' | 'file';
  raw: string;                  // 원문 (실패 시 사용자에게 그대로 보여줌). DB에는 저장하지 않는다
  failReason: string | null;    // 실패한 이유 (status가 failed일 때)
};
```

## 3. 공통 규칙
- 파서는 카드사/은행별로 파일을 나눈다. (`samsungCard.ts`, `hanaBank.ts` 식) 새 형식이 생기면 **기존 파서를 고치지 말고 파일을 추가**한다. 여러 파서가 같이 쓰는 도구(금액 변환, 날짜 해석)는 `common.ts`에 둔다.
- 인식 실패한 줄은 버리지 않고 `status: 'failed'`로 미리보기에 빨간색으로 보여주고, 사용자가 직접 고치게 한다.
- 저장 전에는 항상 **미리보기 → 사용자 확인**을 거친다.
- 금액은 콤마·"원"·띄어쓰기를 제거해 정수로 바꾼다. 소수점은 쓰지 않는다. 취소 건도 `amount`는 양수이고 `isCancel`로 구분한다.
- 연도가 없는 날짜(`10/18`)는 **오늘 기준 가장 가까운 과거(오늘 포함) 날짜**로 해석한다. (예: 1월에 `12/30`이면 작년)
- 전체 카드번호·계좌번호가 문구에 있어도 저장하지 않는다. 끝자리만 `accountHint.digits`로 쓴다. (계좌 `123******45678`은 끝 4자리 `5678`)
- **`누적`·`잔액` 금액은 결제 금액이 아니다.** 결과에 넣지 않고 저장하지 않는다. (같은 카드의 승인·취소 순서와 부호를 검증하는 참고용으로만 쓸 수 있다)
- **`(1회차)` 같은 표기는 할부가 아니다.** 우리카드 명세서의 `국내일시불일부결제금액이월약정(리볼빙)(1회차)`는 리볼빙 표기다. 할부는 `N개월` 또는 `할부`가 **명시된** 경우에만 인식한다.
- 결제명 끝에 글자 수 제한으로 잘린 `(`가 남으면 지운다. (`샘플택시(` → `샘플택시`)
- 메모(`memo`)와 하루 정리는 파서가 만들지 않는다. 저장한 뒤 내역 상세에서 추가한다.
- 코드와 테스트 샘플에는 **이름·번호·금액을 임의 값으로 바꾼 것**만 쓴다. 실제 캡처 이미지는 저장소에 넣지 않는다.

## 4. 인식 규칙

### 4-1. 문자 여러 건 분리 (`splitMessages`)
- `[Web발신]`, `[국제발신]`, `[SMS]`가 나올 때마다 새 문자로 나눈다. 없으면 빈 줄(연속 줄바꿈)로 나누고, 그래도 하나면 한 건으로 본다.
- 카카오톡 등에서 복사하며 섞이는 **시간 줄**(`오전 10:52`, `오후 3:07`)과 **날짜 구분선**(`2026년 10월 31일 토요일`)은 지운다.
- 글자 수 때문에 줄이 바뀐 문자(`누적820,061` 다음 줄에 `원`)는 줄바꿈을 공백으로 합쳐서 읽는다.

### 4-2. 카드 승인·취소 문자
형식: `<카드사><끝자리>(승인|취소) [가려진 이름(님)] <금액>원 <일시불|N개월> <MM/DD> <HH:mm> <가맹점> [누적<금액>원]`
- 카드사 표기 3가지: `삼성1234승인`, `하나56승인`(끝자리 2자리), `우리(5678)승인`(괄호). 줄바꿈 위치는 제각각이다.
- `취소` → `isCancel = true`. 같은 가게·같은 금액의 취소가 몇 분 간격으로 2건 올 수 있다 (둘 다 진짜다).
- `무이자`가 있으면 `interestFree = true`.

### 4-3. 카드 자동결제 접수 문자
형식: `[<카드사>카드]<끝자리> 자동결제 <MM/DD>접수 <결제명> <금액>원`
- **시각이 없다** (`time = null`). 날짜는 "접수일"이라 카드앱 승인일과 하루 다를 수 있다. (중복 판정에서 ±1일을 허용하는 이유)

### 4-4. 통장 거래 문자
형식: `<은행>,<MM/DD> <HH:mm> <가려진 계좌번호> (출금|입금)<금액>원 <내용>`
- `출금` → `direction: 'expense'`, 지출로 저장 대상
- `입금` → `direction: 'income'`, **기본 해제 상태**로 미리보기에 표시 (지출이 아니므로)
- 은행명과 끝 4자리가 등록된 통장과 일치하면 해당 통장을 자동 선택
- 잔액은 저장하지 않는다.

### 4-5. 할부·무이자 문자 (추정 형식)
- 실제 문자 샘플이 아직 없어 형식을 추정했다: `... 120,000원 3개월 ...`, `... 3개월(무이자) ...`. 실제 샘플이 생기면 **파일을 추가**해서 보강한다. 인식하지 못하면 실패로 표시한다.

### 4-6. 카드앱 캡처 (AI, 단계 7-B·7-C)
- 서버 함수가 Claude에게 이미지를 보내 JSON으로 받는다. **서버가 결과를 다시 검증**하고(날짜 형식, 양수 정수 금액, 건수 상한) 전체 카드·계좌번호 모양은 지운다.
- 앱 화면마다 모양이 다르다. 이렇게 읽는다.
  - 날짜가 **건마다** 있는 앱(삼성): 건마다의 날짜·시각을 쓴다. 날짜 머리글(`10월 28일 수요일`)은 쓰지 않는다.
  - 날짜가 **머리글에만** 있는 앱(현대, 우리): 머리글 날짜를 아래 건들에 적용한다. `26. 10. 29 (목)`은 연도 포함, `10월 01일`은 연도 없음(공통 규칙으로 해석).
  - 건마다 적힌 카드 이름(`네이버 현대카드 Ed2`), 끝자리(`본인9300`)는 `accountHint`로 쓴다. 카드 그림만 있는 앱은 이용자가 올릴 때 고른 결제수단을 쓴다.
- **거래가 아닌 것은 제외한다**: 광고 띠(`통신요금 최대 15,000원 할인`), 포인트·적립 예정 줄, 떠 있는 메뉴 버튼, 안내 문구. 제외한 것은 `ignored`에 이유와 함께 돌려준다.
- 읽을 수 없거나 자신 없는 값은 지어내지 말고 `null`로 두고 `warnings`에 적는다. 결과는 모두 미리보기에서 이용자가 확인한다.
- 이용자 동의, 월 이용 한도, 키 관리는 `DATA_MODEL.md` 9~10)번과 `SETUP_GUIDE.md` 12장을 따른다.

## 5. 미리보기 화면
- PC(1100px 이상)는 넓은 표, 모바일은 줄마다 카드 형태. 담는 정보와 동작은 같다.
- 행마다 체크박스(저장 대상 선택), 각 칸 수정 가능
- 결제수단 **일괄 지정** (붙여넣기·캡처·파일 공통). `accountHint`가 등록된 결제수단과 맞으면 자동 선택하되 이용자가 바꿀 수 있다.
- 상태 표시
  - `중복`: 이미 저장된 내역과 같음 → 기본 해제
  - `중복 가능`: 비슷한 내역이 이미 있음(날짜 ±1일, 결제명이 조금 다름) → 기본 해제, 이용자가 판단
  - `입금`: 통장 입금 → 기본 해제
  - `실패`: 인식 실패 → 빨간색, 직접 수정 필요 (원문 함께 표시)
  - `⚠ 실적 제외 가능 · 사유`: 카드 내역에 제외 키워드가 있을 때 (`PERFORMANCE_SPEC.md` 6장)
- 고정지출 규칙(`fixed_rules`)에 맞는 결제명은 자동으로 고정지출 종류를 채운다. (수정 가능, 단계 8)
- 맨 아래에 "저장 N건 / 제외 N건 / 실패 N건" 요약

## 6. 중복 방지 (v0.6 개정)
- **지문(`import_hash`)** = `v1:` + (결제수단 id, 날짜, 시각(있으면), 결제명(공백·기호 제거·소문자), 금액, 취소 여부)로 만든 값. 결제수단이 아직 정해지지 않으면 정해진 뒤에 만든다.
- **시각을 지문에 넣는다.** 같은 날 같은 가게에서 같은 금액을 몇 분 간격으로 취소한 2건(샘플의 하나 카드 취소 2건)이 "중복"으로 오판되지 않게 하기 위해서다.
- **개수로 비교한다.** 저장된 내역에 같은 지문이 N건, 붙여넣은 것이 M건이면 앞의 N건만 `중복`이고 나머지는 새 내역이다. 같은 지문이 한 번에 여러 건이면 지문 뒤에 순번(`#2`)을 붙여 DB의 유일 규칙(`user_id, import_hash`)을 지킨다.
- **`중복 가능` 후보**: 같은 결제수단·**같은 금액**이면서 (날짜 차이가 1일 이내 **그리고** 결제명이 비슷함)일 때. 결제명이 비슷하다는 것은 정규화한 이름이 서로 포함하거나 앞 4글자 이상이 같은 경우다. (예: `Adobe` ↔ `Adobe Adobe`, `KT 유선상품 자동(4960)` ↔ `KT 유선상품 자동납부 09월 - 4960`)
- **금액이 다르면 중복으로 보지 않는다.** 같은 날 같은 가맹점이라도 마찬가지다. (샘플: 같은 구독료가 문자 45,900원, 명세서 29,900원)
- 직접 입력한 내역(`import_hash` 없음)과도 비교한다.
- **이미 가져온 내역(지문 있음)과는 지문이 같을 때만 확정 `중복`이다.** 날짜·결제명·금액이 같아도 시각이 있는 새 문자의 지문이 다르면(시각이 다른 별개 결제일 수 있어서) `중복 가능`으로 둔다. 새 문자에 시각이 없으면(자동결제 접수) 같은 날·같은 결제명·같은 금액을 `중복`으로 본다.
- 지문의 순번 표기는 `v1:` + 14자리 16진수 + (2번째부터) `#2`, `#3`이다.
- 위 판정은 **기본 선택 상태만** 정한다. 최종 결정은 항상 사용자가 미리보기에서 한다.

### 7-5. 최소 테스트 목록
| 상황 | 기대 결과 |
|------|-----------|
| 카드 승인 문자 1건 (S2) | 날짜·시각·금액·가맹점·카드사·끝자리 추출, 누적은 결과에 없음 |
| 카드사별 표기 3가지 (삼성·하나·우리) | 각각 추출. 끝자리 2자리(`하나56`)와 괄호(`우리(5678)`) 포함 |
| 줄바꿈 위치가 제각각 (S4~S9) | 같은 결과 |
| 문자 여러 건 붙여넣기 (S2+S3+카톡 시간 줄) | 건별로 분리, `오전 10:52` 같은 줄은 무시 |
| 취소 문자 (S5, S6) | `isCancel = true`, 두 건 모두 별개로 인식 |
| 결제명이 `(`로 잘림 (S3) | `(` 제거 |
| 자동결제 접수 (S1) | `time = null`, 날짜 = 접수일 |
| 3개월 할부 / 무이자 (E1, E2) | `installment = 3` / `interestFree = true` |
| 통장 출금·입금 (B1, B2) | `expense` / `income`, 계좌 끝 4자리 `5678` |
| 연도 없는 날짜 | 오늘 기준 가장 가까운 과거. 1월 5일에 `12/30` → 작년 |

## 8. 준비된 샘플과 부족한 샘플
- 있음: 카드 문자 3사(삼성·하나·우리), 취소, 자동결제 접수, 통장 출금·입금, 카드앱 캡처 3종(삼성·현대·우리 명세서)
- 부족: 할부·무이자·해외결제·현금영수증 문자, 신한·국민·현대·롯데 문자, 4번째 앱 캡처, 엑셀/CSV 파일
- 부족한 형식은 **실패로 표시되어 직접 고칠 수 있다.** 새 형식은 파서 파일을 추가해서 넓힌다.
