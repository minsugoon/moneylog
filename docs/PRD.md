## 1. 왜 만드는가
- 기존 스프레드시트는 구조는 좋았지만 **입력이 귀찮아서** 유지가 어려웠다.
- 분류(식비/교통 등)는 귀찮으므로 하지 않는다. "어디에 얼마 썼는지"만 본다.
- 목표: 입력 노동을 "붙여넣기 + 틀린 것만 수정"으로 줄인다.
- 제휴카드는 월 실적을 못 채우면 렌탈·통신 할인을 놓친다. 이번 달 실적이 얼마나 남았는지 한눈에 보여준다.
- 실적에 안 잡히는 결제(세금, 상품권, 관리비 등)를 실적으로 착각하지 않도록 미리 알려준다.

## 2. 사용자
- 1차: 본인(1인 사용). PC와 모바일 모두에서 사용.
- 확장 계획: 정식 서비스로 런칭할 계획이다. 누구나 가입할 수 있도록 회원가입·로그인·데이터 분리는 처음부터 적용한다.

## 3. 핵심 원칙
1. 분류하지 않는다. (실적 제외 표시는 지출 분류가 아니라 "실적 계산용 경고"이다.)
2. 입력은 최소 터치.
3. 내 데이터는 나만 본다 (로그인 + RLS).
4. 전체 계좌번호·카드번호는 저장하지 않는다 (끝 4자리만).
5. 카드 실적 규칙은 카드사마다 달라서 코드에 고정하지 않고, 사용자가 직접 설정한다.
6. 앱의 제외 판단은 "추정"이다. 최종 결정은 항상 사용자가 한다.

## 5. 화면 목록
1. 로그인
2. 내역(홈): 월 이동, 월 합계, 리스트, 상단에 카드 실적 요약 띠, 제외 가능 내역에 ⚠ 배지, **지출 메모와 날짜별 하루 정리 표시**
3. 입력: 직접입력 / 파일 / 붙여넣기 / 문자 (탭). 미리보기 표에도 ⚠ 배지 표시
4. 보기: 고정지출 / 기간별 / 결제수단별 / 카드 실적 (탭)
5. 설정: 결제수단 관리, 고정지출 규칙 관리, 카드 실적·혜택 관리, 실적 제외 규칙 관리
- 모바일: 하단 탭 4개 / PC: 좌측 사이드바 + 오른쪽 빠른 입력 패널 (자세히는 5-1장)

### 화면별 핵심 동작
- **내역**: 월 이동, 월 합계, 날짜순 리스트. 항목을 누르면 수정/삭제(삭제 전 확인). 결제수단은 `카카오뱅크 · 월급통장 (1234)` 형식으로 표시.
- **입력(직접)**: 사용일 기본 오늘, 결제수단은 칩 버튼으로 선택, 마지막 선택 기억, **메모(선택) 한 줄**, 저장 후 폼 비우고 연속 입력. 폼 아래에 **"오늘 하루 정리" 카드**(그날 입력한 지출 건수·합계 표시 + 자유 글쓰기, 자동 저장). 날짜를 바꾸면 그 날짜의 정리가 열린다.
- **입력(붙여넣기/문자/파일)**: 저장 전 미리보기 표. 행별 체크/해제와 수정, 결제수단 일괄 지정, 중복 표시(기본 해제), 인식 실패 줄은 빨간색.
- **보기**: 고정지출(종류별 소계·총합), 기간별(이번 달/지난 달/3개월/올해/직접 선택, 월별 막대그래프), 결제수단별(종류별 소계와 비중), 카드 실적.
- **설정**: 결제수단 등록·수정·삭제·순서변경·사용중지, 고정지출 규칙, 카드 실적·혜택, 제외 규칙.

## 5-1. PC와 모바일 구성 (v0.5 신설)

### 결정: 앱은 하나, 화면 배치는 둘
- 주소, 코드, 데이터는 하나다 (`moneylog.vibecodelab.dev`). 화면 폭에 따라 배치가 달라진다.
- PC용 앱과 모바일용 앱을 따로 만들지 않는다. 이유는 세 가지다.
  1. PC에서 입력한 내역이 폰에 바로 보여야 한다.
  2. 고칠 곳이 한 곳이어야 한다.
  3. 초보 개발자가 관리할 코드가 절반이다.
- 모바일은 PWA로 홈 화면에 설치해 앱처럼 쓴다. PC도 크롬·엣지에서 같은 방식으로 설치할 수 있다. (8-1장)

### 화면 폭 기준
| 구분 | 화면 폭 | 기기 예시 |
|------|---------|-----------|
| 모바일 | 767px 이하 | 폰 |
| 태블릿 | 768~1099px | 태블릿, 좁은 창 |
| PC | 1100px 이상 | 노트북, 데스크톱 |

### 구분표
| 항목 | 모바일 | PC |
|------|--------|----|
| 이동 메뉴 | 하단 탭 4개 | 좌측 사이드바 |
| 화면 배치 | 한 열, 한 번에 한 화면 | 3열: 사이드바 · 본문 · 오른쪽 패널 |
| 오른쪽 패널 | 없음 | 내역·보기 화면에서 "빠른 입력"(+ 하루 정리)을 항상 표시. 목록을 보면서 바로 입력 |
| 주력 입력 방식 | 직접 입력, 결제 문자 붙여넣기 (그 자리에서 짧게) | 카드앱 붙여넣기, 엑셀/CSV 업로드, 한 달 치 정리 (몰아서 길게) |
| 미리보기 표 | 줄마다 카드 형태 | 가로로 넓은 표 형태 |
| 카드 실적 | 카드 한 장씩 세로 목록 | 프로그램 카드를 2열로 나란히 |
| 입력 도구 | 숫자 키패드, 큰 버튼(44px 이상), 칩 선택 | 키보드로 이어 입력 (Tab 이동, Enter 저장) |
| 설치 | 홈 화면에 추가 (PWA) | 주소창 설치 아이콘 (선택) |
| 하단 여백 | 홈 인디케이터 영역(safe-area)을 피함 | 해당 없음 |

### 규칙
- 기능과 데이터는 두 화면이 완전히 같다. PC에만 있거나 모바일에만 있는 기능은 없다. 배치와 편의만 다르다.
- 화면 폭 판단은 CSS(Tailwind 반응형 클래스)로 한다. 기기를 알아내는 코드(`userAgent` 검사)는 쓰지 않는다.
- 화면 틀(하단 탭, 사이드바, 오른쪽 패널)은 `components/layout/`에 모은다.
- 개발할 때마다 폰 화면(약 400px)과 PC 화면(1280px 이상) 둘 다 확인한다.

## 7. 계산 규칙 (할부·취소)
- 실결제액 = 이용금액 - 할인
- 월 납부액 = 실결제액 / 할부개월 (원 단위 반올림, 마지막 회차에서 오차 보정)
- 회차 = (선택월 - 사용월) + 1, 잔액 = 실결제액 - 월 납부액 × 회차
- 보기 기준 토글: 사용일 기준 / 월 납부액 기준
- 취소 건(`is_cancel`)은 금액을 마이너스로 계산한다. (일반 합계와 실적 계산 모두)

## 8. 비기능 요구사항
- 모바일 우선, 버튼 최소 44px, 입력창 글자 16px 이상(iOS 확대 방지)
- 금액은 정수(원), 천 단위 콤마
- 로딩/빈 화면/오류 문구는 친절한 한국어
- 삭제 전 확인
- 보안: anon key만 사용, service_role 키는 코드·GitHub에 절대 금지, .env는 .gitignore
- 계산·판정 로직(`installment.ts`, `performance.ts`, `exclusion.ts`)과 파서는 테스트 파일을 반드시 같이 만든다.

| 실행 모양 | 설치한 앱은 주소창 없이 전체 화면(standalone)으로 열린다 |
| 앱 이름 | Moneylog (홈 화면 이름도 Moneylog) |
| 아이콘 | 192×192, 512×512, 마스커블 512×512, 아이폰용 180×180. 처음에는 임시 아이콘(파란 바탕에 글자 M), 나중에 교체 |
| 색상 | 테마 색 `#2C4DD6`, 배경 색 `#F2F4F9` |
| 오프라인 | 인터넷이 없어도 앱 껍데기(화면)는 열린다. 내역 데이터는 항상 서버(Supabase)에서 최신으로 불러오고 기기에 저장해 두지 않는다. 오프라인 입력 보관은 V2 |
| 업데이트 | 새 버전을 배포하면 다음에 앱을 열 때 자동으로 바뀐다 |
| 로그인 | 구글 로그인(기본) + 이메일+비밀번호(예비). 이메일 링크(매직링크) 로그인은 쓰지 않는다. 아이폰에서 링크가 설치한 앱이 아닌 Safari로 열려 로그인이 끊기기 때문이다. 구글 로그인도 바깥 페이지를 거치므로 아이폰 설치 앱에서 반드시 확인하고, 끊기면 이메일+비밀번호로 대신한다 |
| 보안 | 서비스워커(앱의 캐시 담당)가 로그인 정보나 내역 응답을 캐시하지 않는다 |
| 필수 조건 | HTTPS (Vercel이 제공) |
| 확인 | 아이폰 Safari, 안드로이드 Chrome, PC 크롬 세 곳에서 설치와 실행을 확인한다 |

## 9. 기술 스택
Vite + React + TypeScript + Tailwind + vite-plugin-pwa / Supabase / GitHub(Private) / Vercel / Cloudflare(DNS)

## 10. 성공 기준
- 한 달 치 카드 내역을 붙여넣어 3분 안에 저장된다.
- 일주일에 한 번만 입력해도 부담이 없다.
- 폰과 PC에서 같은 데이터가 보인다.
- 가진 제휴카드 실적을 모두 등록하고, 월말 전에 부족한 금액을 한눈에 확인할 수 있다.
- 실적 때문에 할인을 놓치는 달이 없다.
- 이 앱의 실적 수치가 카드사 앱 수치와 큰 차이 없이 맞는다. (첫 달 대조 후 설정 보정)
- 폰 홈 화면 아이콘으로 열면 주소창 없이 앱처럼 열리고, 로그인이 유지된다.
- PC에서는 내역 목록을 보면서 오른쪽 패널로 바로 입력할 수 있다.

## 11. 위험 요소와 대응
| 위험 | 대응 |
|------|------|
| 카드사별 형식이 달라 인식 실패 | 미리보기·수정 단계, 파서를 카드사별 파일로 분리, 실제 샘플로 개선 |
| 개인 금융정보 유출 | 비공개 저장소, RLS, 끝 4자리만 저장 |
| 초보라 막힘 | 단계마다 "완료 확인" 후 커밋, 막히면 이전 커밋으로 복귀 |
| 앱 실적과 카드사 실적이 다름 | 처리 방식·내역별 확정으로 보정, "참고용" 문구, 첫 달 대조 |
| 실적 규칙이 너무 다양함 | 코드에 고정하지 않고 사용자 설정 방식으로 설계 |
| 제외 키워드 오인식(과잉/누락) | 배지는 "가능성"으로만 표현, 사용자 확정 우선, 키워드 직접 추가·삭제 |
| 제외 기준이 카드사 정책 변경으로 달라짐 | 기본 키워드는 참고용임을 안내, 카드 약관 확인 권장 문구 |
| 아이폰 설치 앱에서 로그인이 끊김 | 이메일 링크 로그인을 쓰지 않음. 구글 로그인이 끊기면 이메일+비밀번호로 대신할 수 있게 둘 다 제공 |
| 서비스워커가 내역을 기기에 남김 | 앱 껍데기만 캐시, Supabase 요청은 캐시하지 않음 |
| PC·모바일 화면이 따로 놀아 고칠 곳이 늘어남 | 코드 한 벌, 화면 틀만 `components/layout/`에서 분리 |

## 12. 미정 사항 (진행하며 결정)
- 주로 쓰는 카드/은행 목록과 실제 내역 샘플
- 수입(입금) 기록을 MVP에 넣을지 여부 (`type` 칸을 미리 넣을지 포함)
- Apple 로그인 등 추가 로그인 방식 (정식 런칭 단계에서 추가 예정)
- 정식 런칭 전 준비: 개인정보 처리방침·이용약관, 구글 로그인 동의 화면 검수, 검색 노출(noindex) 재검토, 비밀번호 찾기
- 가진 제휴카드의 실제 실적 조건 목록 (카드명, 목표액, 측정 방식, 혜택, 제외 항목)
- 월별 달성 여부를 저장할지(F18), 화면에서 계산만 할지
- 메모·하루 정리 검색, 하루 정리 기분 표시, 월간 회고 보기를 추가할지
- 앱 아이콘 디자인 (임시 아이콘으로 시작)
- PC 키보드 단축키(예: N 새 입력)를 추가할지
- B등급 제외 항목의 기본 처리 방식을 `표시만`으로 둘지, 일부는 `제외`로 바꿀지
