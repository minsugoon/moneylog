# 영수증 사진 입력 — 가능 여부 보고서 (F27)

- 작성: 2026-10-31 / 상태: **검토용. 구현 전.**
- 목적: 영수증 사진에서 **상호명, 날짜, 합계 금액, 카드 이름**을 읽어 미리보기로 보여줄 수 있는지 판단한다.
- 주의: 이 보고서는 **실제 영수증으로 시험하기 전**에 쓴 것이다. 현재 만든 캡처 입력(7-C)의 구조와 일반적인 AI 이미지 읽기 능력을 바탕으로 한 **예상**이며, 읽기 성공 비율은 아직 측정하지 않았다.

## 1. 결론
- **만들 수 있다. 다만 "정확히 읽힌다"고 약속할 수는 없고, 미리보기에서 사용자가 확인·수정하는 전제로 쓸모가 있다.**
- 4가지 항목의 예상 난이도
  | 항목 | 예상 | 이유 |
  |------|------|------|
  | 날짜 | 비교적 쉬움 | 대부분 영수증에 "승인일시·거래일시" 형태로 찍힘 |
  | 합계 금액 | 보통 | "합계·결제금액·받을금액"이 가게마다 다르고, 할인·쿠폰·포인트·부가세·거스름돈이 섞여 있음 |
  | 상호명 | 보통 | 맨 위 큰 글씨가 브랜드명이고 아래 작은 글씨가 실제 가맹점명인 경우가 많음 |
  | 카드 이름 | **어려움** | 아래 2번 참고 |
- 지금 앱의 입력 구조(동의, 월 한도, 이미지 줄이기, 서버 검증, 미리보기, 중복 표시)는 **그대로 쓸 수 있다.** 새로 만드는 양은 작다(7번).

## 2. 카드 이름이 어려운 이유
- 신용카드 영수증에는 **발급사(카드 주인이 가진 카드)** 와 **매입사(가맹점이 돈을 받는 카드사)** 가 나란히 찍힌다. 둘이 다를 수 있어서 AI가 엉뚱한 쪽을 읽으면 결제수단이 잘못 선택된다.
- 번호는 가려진 채 끝 4자리만 나오는 경우가 많고, 아예 안 나오는 곳도 있다. 간편결제(삼성페이·카카오페이 등)나 체크카드는 표기가 또 다르다.
- 앱은 카드사 이름과 끝 4자리가 둘 다 맞을 때만 결제수단을 자동 선택한다. 못 읽으면 "선택 안 함"으로 두고 사용자가 고른다. 틀린 카드가 자동 선택될 위험을 줄이려면 **발급사만 쓰고, 애매하면 비워 두라고 지시문에 적어야 한다.**
- 현금 영수증이나 현금 결제는 카드 정보가 없으므로 결제수단을 직접 "현금"으로 고르는 흐름이 맞다.

## 3. 영수증이 캡처보다 어려운 점
| 문제 | 영향 | 대응 |
|------|------|------|
| 영수증이 세로로 매우 긴 경우 | 지금은 긴 변을 1568px로 줄여서 보낸다. 글자가 작아져 읽기 어려울 수 있다 | 시험에서 확인. 필요하면 "윗부분(상호·날짜)과 아랫부분(합계·카드)을 따로 찍기" 안내 또는 긴 이미지 자르기(그만큼 장수 차감) |
| 구겨짐, 빛 반사, 비스듬한 촬영, 흐림 | 읽기 실패나 숫자 오독 | 미리보기·수정 필수. 못 읽은 값은 비워서 표시 |
| 오래된 감열지 영수증의 흐린 글자 | 금액 오독 | 위와 같음 |
| 할인·쿠폰·포인트 사용, 분할결제(카드+현금) | 합계가 여러 개로 보임 | 지시문에 "실제 카드로 결제한 금액"을 우선하라고 적고, 여러 값이 보이면 실패로 표시 |
| 취소 영수증, 할부, 해외 결제 | 취소·할부 여부 오인 | 캡처 모드와 같은 규칙 사용. 처음엔 취소·해외는 "실패" 표시로 두는 것도 방법 |
| 사진에 카드번호 전체·이름·사업자번호가 함께 찍힘 | 개인정보가 AI 회사로 전송됨 | 동의 안내문에 영수증용 문구 추가(가릴 수 있으면 가리기). 앱은 끝 4자리만 저장 |
| 이미 카드 문자·캡처로 저장한 결제를 영수증으로 또 입력 | 중복 | 날짜가 같고 상호명이 비슷하면 "중복 가능"으로 표시되지만, 결제수단을 다르게 고르면 놓칠 수 있음 |

## 4. 지금 구조로 바로 되는 것
- 서버 함수는 이미지를 최대 5장, 1장당 base64 약 3MB까지 받는다. 영수증 사진 1장은 보통 충분하다(앱이 JPEG로 줄여 보낸다).
- 결과 모양(`ParsedRow`)에는 날짜, 시각, 가맹점, 금액, 취소, 카드사·끝 4자리 힌트가 이미 있다. **영수증은 같은 모양에 1건을 채우면 된다.**
- AI가 낸 값은 서버에서 한 번 더 검사한다(없는 날짜, 음수 금액, 이상한 카드번호는 "실패"로 표시). 영수증에도 그대로 적용된다.
- 이미지는 서버에 저장하지 않고, 사용 횟수만 기록한다.
- 비용: 이미지 1장 기준은 캡처와 비슷하다. 영수증은 읽을 글이 적어 출력은 더 짧을 것이다. 실측은 7-D·7-E 시험에서 한다.

## 5. 새로 필요한 것 (구현한다면)
1. **서버 함수 지시문에 영수증 모드 추가** — 요청에 `kind: "receipt"`를 받아 지시문을 바꿈. 서버 함수 배포 승인 필요.
2. **동의 안내문 수정** — "카드앱 캡처"만 말하고 있어 "영수증 사진" 문구 추가. 안내문 변경 승인 필요.
3. **입력 탭에 영수증 선택** — 폰에서는 카메라가 바로 열리는 파일 입력(`capture` 속성), PC에서는 사진 파일 선택. 새 탭을 만들지 캡처 탭 안에서 종류만 고르게 할지는 시험 후 결정.
4. **이미지 줄이기 기준 점검** — 긴 영수증용으로 기준 변경 필요 여부는 시험으로 결정.
5. 테스트: 서버 순수 로직(영수증 지시문, 값 검증)은 기존처럼 테스트 파일과 함께 만든다.
- 예상 크기: Codex 작업 2건 안팎(서버 함수는 Claude가 직접 작성했던 7-B 방식 가능). DB 변경은 필요 없다(`source`는 `paste`로 저장).

## 6. 위험과 한계
- **정확도는 가게마다 들쭉날쭉할 것이다.** 영수증은 형식 표준이 없다. "대부분 맞다"가 아니라 "미리보기에서 자주 고쳐야 한다" 수준일 수도 있다. 시험 전에는 알 수 없다.
- 틀린 값이 그럴듯하게 나오면 사용자가 못 알아채고 저장할 수 있다. 미리보기에서 **원본 영수증과 나란히 비교**하기 쉽게 하는 것이 중요하다(이미지를 앱에 남기지 않는 규칙 때문에, 사용자가 자기 폰의 사진을 보며 확인).
- 월 20장 한도를 영수증이 빨리 소진할 수 있다(영수증 한 장도 1장). 한도를 올리는 것은 별도 승인 사항이다.
- 직접 입력(날짜, 상호명, 금액)이 영수증 사진을 올리는 것보다 빠를 때도 있다. 이 기능은 "가끔 쓰는 보조 입력"으로 보는 것이 현실적이다.

## 7. 권장 진행
1. **7-E 시험(구현 전)**: 사용자가 실제 영수증 10장 안팎(편의점, 식당, 마트, 카페, 약국, 오래된 감열지, 구겨진 것, 현금·카드 섞어서)을 준비한다. 번호·이름은 가려서 올린다.
2. 같은 영수증을 Haiku 5.5와 Sonnet 5.5로 읽혀 4가지 항목의 "한 번에 제대로" 비율과 비용을 비교한다(7-D와 함께).
3. 기준 제안: **상호명·날짜·합계가 대부분(예: 10장 중 7장 이상) 맞고, 카드 이름은 틀리지 않게 비워 두는 쪽이면 구현**한다. 그보다 낮으면 보류하고 직접 입력·카드 문자 입력을 권한다.
4. 시험은 월 한도 20장 중 10장 안팎을 쓰므로, 7-D 시험 장수와 합쳐 계획한다.

## 7-1. 샘플 영수증 5장을 눈으로 살펴본 메모 (2026-11-01)
- 사용자가 시험용 영수증 사진 5장을 올렸다(식당 2, 카페 1, 옷가게 2). **서버 함수·Haiku·Sonnet으로 읽힌 결과가 아니라, Claude(채팅)가 사진을 직접 보고 정리한 것**이라 앱의 정확도 수치로 쓸 수 없다. 정답표를 만드는 데만 쓴다. 개인정보(이름, 전화번호, 사업자번호)는 이 문서에 옮기지 않는다.
- 5장 모두 날짜·합계·카드 종류가 보였고, 상호명은 1장(접힌 자국이 글자를 가림)이 애매했다. 한 장은 연도 글자가 번져 있었다.
- 발견한 어려운 점
  | 장 | 어려운 점 |
  |----|-----------|
  | 1 | 카드 칸에 "네이버 Ed2"(카드 상품명)만 있고 "현대카드"는 **매입사** 칸에 따로 있다. 끝자리는 `340*`처럼 한 글자가 가려져 있다 |
  | 2 | 합계·받을금액·받은금액이 모두 같다. 카드는 "[현대비자개인]"이고 끝 4자리가 보인다 |
  | 3 | 상호명이 구겨진 자국에 반쯤 가려졌고, 날짜가 두 곳(판매시간 12:23:52, 승인일시 12:24:02)이며 초가 다르다. 카드번호 뒤쪽은 전부 `*` |
  | 4 | 글자가 흐릿하고 구멍이 있으며 연도(`202?`)가 번졌다. 카드 번호는 앞 6자리만 보이고 끝 4자리는 없다. 품목이 많고 상호는 법인명이다 |
  | 5 | 카드 칸은 "신용카드"뿐이고 매입사만 "현대"다. 카드번호는 전부 가려져 끝 4자리가 없다. 품목별 할인이 있고 "결제금액"이 합계 역할을 한다 |
- 알게 된 것
  1. **카드 이름 표기가 영수증마다 전부 다르다**: 상품명(네이버 Ed2), 상품 종류(현대비자개인), 카드사(현대카드, NH카드), 그냥 "신용카드". "카드 이름"을 하나의 글자로 정해 앱 결제수단과 맞추는 건 어렵다.
  2. **끝 4자리가 5장 중 1장에만 온전히 보인다.** 앱의 자동 결제수단 선택(카드사 + 끝 4자리)은 영수증에서는 거의 작동하지 않을 것이다. → 영수증은 **사용자가 결제수단을 직접 고르는 것이 기본**이어야 하고, 자동 선택은 있으면 쓰는 보조다. 지금 캡처 탭처럼 "어느 결제수단의 영수증인가요?"를 먼저 고르는 흐름이 맞다.
  3. 합계에 해당하는 이름이 "합계", "받을금액", "결제금액", "카드매출"로 다양하다. "카드로 낸 금액"을 찾으라는 지시가 필요하다.
  4. 상호명은 영수증 맨 위가 아니라 "[매장명]" 같은 칸에 있거나(5번) 법인명(4번)일 수 있다. 사람이 부르는 이름과 다를 수 있어 미리보기에서 고치는 흐름이 필수다.
- 정답표(채점용, 사용자 확인 필요): 날짜 / 합계 / 카드 힌트 (상호명은 보이는 그대로)
  | 장 | 날짜 | 합계 | 카드 힌트 | 상호명 |
  |----|------|------|-----------|--------|
  | 1 | 2026-10-29 19:38 | 10,000 | 네이버 Ed2 (매입사 현대) | 만두 가게(바불리 옛날왕만두) |
  | 2 | 2026-10-26 12:29 | 7,800 | 현대비자개인, 끝 3402 | 카페와이(CafeYCoffee) |
  | 3 | 2026-10-29 12:23 | 25,600 | 현대카드, 끝자리 없음 | 라멘집 (글자가 일부 가려짐) |
  | 4 | 2026-10-15 19:49 | 258,000 | NH카드, 끝자리 없음 | (주)에스에프비 |
  | 5 | 2026-10-24 17:06 | 229,400 | 신용카드 (매입사 현대), 끝자리 없음 | 신성통상 포천선단점 |
